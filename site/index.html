Los tres pilares

Unas IAs codean pero no ven. Otras ven pero no arreglan. Esta hace las dos.

Así se entregan apps sin crashes, sin layout roto y sin bugs que solo aparecen cuando un usuario real se queja.

01 · Devices

Navegadores reales, perfiles reales

Chromium con perfiles desktop, iphone, pixel e ipad. La IA toca, escribe y navega de verdad, no simula.

02 · Vision

Video, trace y screenshots de cada corrida

Cada paso queda grabado: video, DOM + red + consola, capturas y un snapshot de accesibilidad. Comparador visual contra el mockup aprobado.

03 · Forge Loop

Corre → clasifica → arregla → repite

Cada hallazgo trae severidad, fingerprint para deduplicar y un prompt de fix listo para pegar. El loop no para hasta defectos == 0, con presupuesto de iteraciones.

Gate de entrega · lo que pruebo = lo que entrego

Misma URL, mismo guión. Dos veredictos.

El gate corre contra el build real y bloquea la promoción a producción si hay defectos por encima del umbral. Esto es una corrida real, no un mock.

Cómo se usa

Una URL, un guión, un veredicto.

SDK para meterlo en el flujo de VForge después de generar cada app, o CLI con exit code para CI/CD.

SDK

import { check, deployGate } from "vforge-live";

const result = await check({
  baseUrl: "https://mi-app-preview.vercel.app",
  scenarios: [login],        // scenario-dsl
  failOn: "high",
});

// antes de promover a prod:
const gate = await deployGate({ baseUrl, scenarios });
if (!gate.promote) throw new Error(gate.reason);

CLI · exit code para CI

# contra una URL desplegada
vforge-live check --url https://mi-app.com --scenario flujo.json

# gate estricto: exit 1 = NO promover
vforge-live gate --url https://preview.app --scenario flujo.json \
  --fail-on blocker --bundle

# después del deploy: exit 1 = deploy roto
vforge-live smoke --url https://mi-app.com --expect-text "Bienvenido"
